# SEO audit for dishantsharma.dev

Audit date: 2026-11-25.

This report covers the homepage, the blog list, all 106 articles, the sitemap, and Search Console data.

SEO means work that helps search engines find and understand pages. GSC means Google Search Console.

## Result

Organic search is growing quickly. The main limits are content evidence, article indexation, and the homepage mobile experience.

The site had 122 clicks and 8,443 impressions in the last 28 days. The previous 28 days had 12 clicks and 1,013 impressions.

Google had indexed 73 of 108 sitemap URLs. The other 35 URLs include 34 articles and the blog list.

The live homepage had a severe mobile lab result. Its main text stayed hidden until client JavaScript ran. The code now shows that text immediately.

## Technical audit

### Crawl and index controls

The live sitemap contains 108 unique HTTPS URLs. Every sitemap URL returned HTTP 200.

The robots file allows public pages and blocks `/api/`. It names the sitemap.

Every article has a self-referencing canonical URL. The 404 page had a homepage canonical. The code now removes that canonical.

The homepage linked to `/project/pixr`, which returned 404. The code now uses the GitHub repository URL when a project has no live site.

HTTP still redirects to HTTPS with 302. Cloud Run controls this redirect. A permanent 308 redirect is the preferred deployment change.

The site serves one language. It does not need hreflang tags.

### Metadata

All 106 articles have a title and a description. No exact duplicate titles or descriptions were found.

Twenty-nine titles exceed 60 characters. Character count does not prove truncation because result width also matters.

Three descriptions are shorter than 120 characters. Two exceed 160 characters.

The Canva Brush description is 100 characters and ends with `Canva...`. It does not name Brush or the 46% claim.

The homepage title and description match the person and role. The homepage H1 now includes `Dishant Sharma`.

The blog H1 now names AI coding tools and model reviews.

### Structured data

All rendered JSON-LD blocks parsed as valid JSON.

Articles include `BlogPosting` and `BreadcrumbList`. The author includes a name, type, URL, and shared identifier.

The homepage now includes `ProfilePage` with a nested `Person`. The root layout keeps `WebSite` on every page.

### Security and caching

The live responses lacked HSTS, content-type protection, referrer policy, permissions policy, and frame protection.

The code now adds these headers:

- `Strict-Transport-Security`
- `X-Content-Type-Options`
- `Referrer-Policy`
- `Permissions-Policy`
- `X-Frame-Options`

Blog and article HTML use a one-hour shared cache. Hashed CSS, JavaScript, and fonts use a one-year immutable cache.

The homepage still returns `private, no-cache, no-store`. This prevents shared caching and back/forward caching.

### Images

No image lacked alt text or dimensions in the live crawl.

Article cover images now use `fetchPriority="high"`. This asks the browser to fetch the likely main image first.

Next.js serves optimized modern image formats. The URL extension alone does not prove the served format.

Current article bodies contain no inline images. Future dev.to body images will bypass Next.js image optimization.

## Content audit

The audit examined all 106 metadata records and 22 article bodies.

None of the 22 sampled bodies contained an external source link. None contained a contextual link to another article.

Many posts discuss benchmarks, prices, launches, repositories, or tests without primary sources.

Four posts need content changes before promotion:

- The UI design post promises production-ready output, but the body rejects that claim.
- The Flash-MoE title promises a tutorial, but the body has no command or installation step.
- The MiniMax comparison gives scores and prices without sources.
- The Opus vs Codex post claims a real test without a reproducible method.

One post with 1,273 words has no H2 heading. It uses bold text as section labels.

The titles and descriptions repeat several patterns. Fourteen titles contain `hype`. Eleven contain `actually`. Forty-eight descriptions use `Here is` or `Here's`.

Fifty posts share the publication date 2026-10-04. This suggests an import or bulk publish event.

All 106 dev.to records point to the correct portfolio canonical URL. Canonical ownership is no longer the main technical blocker.

## Fixes made in this repository

- The homepage H1 includes the person name.
- The homepage shows its main text before JavaScript runs.
- The homepage intro links to `/blog`.
- The blog H1 describes its topic.
- Project rows use GitHub when no live URL exists.
- Article bylines link to the About section.
- Related articles use shared tags before publication date.
- Article pages show both publication and update dates.
- Article share metadata has a blog image fallback.
- Article cover images request high fetch priority.
- The homepage emits `ProfilePage` structured data.
- The 404 page has no canonical URL.
- Root metadata uses `NEXT_PUBLIC_SITE_URL`.
- Sitemap entries omit unverified modification dates.
- Security headers protect every route.
- The header no longer loads the full sticker catalog.
- The header no longer makes a failing optional GitHub star request.
- Search Console credentials live in ignored `.gsc-cli/` files.

## Limits
